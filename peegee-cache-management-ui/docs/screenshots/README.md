# Management UI screenshots

Open [the screenshot gallery](index.html). Images are visible immediately, grouped by feature and
described by behavior. Search the gallery or click any image to open its full-size PNG.

This directory follows the sibling PeeGeeQ UI documentation convention: one flat directory of
descriptively named PNGs, not scenario-ID folders. For example:

- `entry-default-valid-json-to-a-structured-tree-viewport.png`
- `entry-default-valid-json-to-a-structured-tree-element.png`

The complete passing Java Playwright run automatically publishes every verified scenario here.
Focused runs do not replace the complete documentation gallery. Both captures are retained for
each scenario; additional browser contexts have a `capture-2` suffix. Internal test IDs remain in
the machine-auditable evidence report, not the user-facing filenames or gallery organization.

To republish an existing verified report without rerunning tests, from the repository root:

```powershell
java -cp peegee-cache-rest/target/test-classes dev.mars.peegeeq.cache.rest.server.ManagementBrowserScreenshotGallery peegee-cache-rest/target/playwright-evidence.html peegee-cache-management-ui/docs/screenshots
```

This copies the original PNG bytes; it does not fabricate new captures or claim a new test run.
PNGs and the generated gallery are ignored build products. This README and the publisher are tracked.

## Capture appearance

Capture the development UI as rendered: no screenshot masks, black rectangles, text suppression,
redaction, replacement values, or canary-based filtering. Empty editors remain empty; visible values
remain readable. Native password controls and application reveal/hide states appear as they do in
the browser. Neither the report nor the gallery alters the captured PNG bytes.

Previously masked PNGs must be regenerated by the browser suite; republishing an old report cannot
restore the pixels that were obscured. A complete passing run replaces the gallery's current images.
